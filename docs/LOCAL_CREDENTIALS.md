# 本地加密凭据（macOS）

## 保存位置与升级

服务器地址、端口、用户名、分组、历史及凭据引用仍保存在应用数据目录的 `noxshell-ops.sqlite3`，不迁移、不清空。密码和私钥口令改为当前用户家目录下固定的：

- `~/.noxshell/credentials.enc`：加密记录，包含凭据引用、密码、私钥口令及已删除记录标记。
- `~/.noxshell/master.key`：安全随机生成的 256 位本地密钥；不是应用内置密码，也不由机器序列号或版本派生。
- `~/.noxshell/vault.lock`：不含密码的跨进程锁文件。

普通覆盖安装只替换 `.app`，不删除以上文件。换应用版本、代码哈希或安装位置不改变密码读取方式；新旧支持本地库的构建可以共用。**降级至采用 Keychain 的旧版不支持读取本地库。** Windows / Linux 保持原生凭据后端。

首次使用新方案时，只针对实际请求的旧引用尝试无交互 Keychain 读取。可读则原引用迁移；不可读时停止，不申请授权、不执行外部 `security` 命令、不修改 ACL。用户可能需要最后补输一次 SSH 密码并选择记住。之后保存到本地库；旧钥匙串条目不自动删除。启动、浏览服务器列表和编辑元数据不批量读取旧密码。

认证恢复界面只在服务器认证成功后保存勾选记住的密码。若写入失败，当前 SSH 会话可继续，但会明确显示未记住的原因。目录权限异常、磁盘写入失败、文件被删除、密钥丢失、服务器修改了密码等仍可能需要处理或重新输入；并非无条件永久免密。

## 安全边界

该方案由用户选择，优先保证跨版本自动读取。采用 OpenSSL EVP AES-256-GCM：每次写入使用随机 96 位 nonce，128 位认证标签；格式头作为附加认证数据，认证失败前不使用解密内容。目录要求当前用户所有、`0700`，文件要求当前用户所有、`0600`；拒绝符号链接、文件硬链接和非普通文件。写入通过同目录临时文件、文件同步、原子替换和目录同步完成；新密钥仅独占创建，不能替换已有密钥。并发修改通过跨进程锁串行化，忙时报告重试，不覆盖其他实例数据。

密钥与密文分文件，但都存于同一用户可访问的磁盘。**能够读取两者的同用户恶意程序或管理员能够解密；此方案不提供 Keychain 的应用签名隔离。** 没有主密码、不请求系统授权，也不以明文配置、Base64 或固定混淆算法代替加密。应用工作时仍须在内存中使用密码，不能防御进程内存读取。建议启用系统磁盘加密，不把整个目录发给他人。

本地加密不改变 SSH 主机指纹校验、算法选择、服务器认证、安全连接或远端采样周期；不新增服务器请求。应用签名/公证和首次安装的 Gatekeeper 检查仍是独立事项，不因本地加密而绕过。

另外检查 macOS 扩展 ACL，避免仅看 `0600` / `0700` 权限位而遗漏额外访问授权。发现非空 ACL 会明确报错，不自动改动已有权限。

## 备份与异常恢复

退出所有玄壳实例后，将主机 SQLite 数据库、`credentials.enc` 和对应 `master.key` 一起备份到可信的加密备份中；不要只备份密文，也不要在应用运行时分别复制不一致的版本。恢复后保持本人所有及上述权限。

已有密文但密钥缺失、只有密钥而数据文件丢失、密钥格式错误、认证标签错误、版本不支持或记录格式损坏时，读取、保存和删除都停止，不新建密钥覆盖，不转而导入旧钥匙串。应先保留整个目录，再恢复同一份备份的密文与密钥。不能恢复密钥时旧密文无法解密；需要用户明确决定重置并重新录入，不自动重置。

删除操作写入加密删除标记，避免在旧钥匙串条目仍存在时再次迁移。旧 Keychain 条目及备份不会因本地删除而消失；本地删除不承诺 SSD 上的物理安全擦除。

## 回归验证

`ctest --test-dir build-release -R local_credential_vault --output-on-failure`

测试只使用临时目录和虚构凭据：两个不同二进制构建互读/更新及重启、并发保存、随机密文、权限、篡改/截断/错误密钥/丢失密钥/超限、链接拒绝、锁冲突、旧密码迁移、迁移竞争与删除不复活。不读取真实 SSH 密码，不连接实际服务器。

实现参考：[OpenSSL EVP AEAD 接口](https://docs.openssl.org/3.0/man3/EVP_EncryptInit/)、[OpenSSL 随机数接口](https://docs.openssl.org/3.0/man3/RAND_bytes/)。
