# 性能与安全说明

## 未发布：本地加密凭据

macOS 已改用固定用户目录的本地加密凭据库，不再把跨版本读取绑定到 Keychain 应用签名。旧 Keychain 仅在本地缺少记录时静默迁移，不能读取的不绕过授权。实现、限制及备份说明见 [本地加密凭据](LOCAL_CREDENTIALS.md)。以下按版本列出的 Keychain 描述为历史实现，不代表当前存储策略。此次变化不增加服务器负载。

## v0.2.66 不请求钥匙串授权

- 移除显式授权 API 和解锁按钮。macOS 读、写、删一律使用串行、进程内关闭交互的作用域；无法建立此作用域就停止操作，结束后恢复原状态。没有 `security` 读取兜底，不修改 ACL、系统全局设置或钥匙串锁定状态。
- 不可读取的旧密码不会被绕过。终端内只要求服务器的 SSH 密码/私钥口令，并直接用于本次 SSH 认证。用户可以选择不记住；若选择记住，认证成功后才创建随机新引用的 Keychain 加密条目。旧条目保留，不批量迁移或删除。
- 引用更新采用数据库比较并交换，检查主机、端口、用户、认证方式、私钥及原引用；不会复活已删除主机或覆盖连接期间的配置更改。只有新条目保存成功后才切换引用；失败仍保留当前 SSH 连接，没有明文落盘兜底。
- 启动/主机浏览不访问密码，编辑元数据不读写密码。连接测试只在已有输入框提示填写 SSH 凭据，RDP 改为远程密码编辑入口。
- 本次不改变未知主机指纹确认、安全算法、服务器配置或监控采样频率。保存期间不发送任何额外远端命令。
- ad-hoc 签名在构建/更新后会变更应用身份，旧密码可能需要重新填写；本版消除的是本应用主动触发的钥匙串授权框，不承诺绕过 macOS 的应用安装安全检查或在锁定的钥匙串中保存密码。稳定的发布签名尚未配置。
- 最终 Release：69 项 UI/逻辑通过，3 项默认跳过；26 项回环 SSH 检查无非预期失败，保留 1 项已知 libssh2 尾部输出 XFAIL。三个原生 Cocoa 输入流程用模拟凭据库验证通过，并检查了实际渲染截图。
- 原生 Keychain 另行启用，仅对随机虚拟条目验证不可读旧条目的静默读/写/删，以及新建条目在 8 个独立限时子进程中的创建、三次重启读取、更新、再次读取及两次删除。最终运行 276 毫秒完成，未弹授权框，测试条目已清理；没有读取真实密码或登录实际服务器。

## v0.2.65 默认静默、按需授权

- `CredentialStore::load` 默认静默。所有自动读取都不请求系统交互；SSH、连接测试、RDP 仅在界面内的解锁按钮被点击后，才使用显式授权模式。启动及主机/历史浏览不读取凭据，单纯编辑元数据不读写旧密码。
- v0.2.64 的 ACL 路径检查不能保证系统工具免授权，因此移除整个 `security` 子进程读取分支。v0.2.62 的读取身份变化是最初的兼容性回归；v0.2.63 只处理重入；v0.2.64 恢复旧读取程序并未彻底解决提示。
- 真实虚拟条目测试发现旧式登录钥匙串不能仅靠 `kSecUseAuthenticationUIFail` 禁止提示。本版同时在本进程内为静默读取临时设置 `SecKeychainSetUserInteractionAllowed(false)`；所有本应用的原生钥匙串操作共用锁，读取结束后恢复先前状态。设置失败则停止读取，不冒险弹窗。此操作不改变系统全局设置、钥匙串锁定状态或条目访问权限。
- 未授权的密码不会被静默绕过：连接停留在可操作的解锁提示，不发起 TCP/SSH 认证。授权成功使用本次结果继续连接，不立即重复读取；拒绝、取消或关闭标签不触发自动授权重试。
- 没有增加密码缓存、明文存储或凭据迁移。原生凭据写入/删除仍仅在用户主动保存/删除时执行，必要时可能由系统要求权限。签名仍为 ad-hoc，应用身份更新可能需要用户主动重新授权；稳定的 Developer ID 发布签名尚未配置。
- 旧凭据测试只操作随机虚拟条目；子进程保留默认交互状态，验证生产代码自身抑制弹窗并恢复进程状态。设置 5 秒超时并由父进程负责清理条目，避免阻塞测试。显式授权 UI 的流程用模拟凭据库验证，不替用户点击系统授权。
- 验证记录：最初只有查询级禁止交互的虚拟测试实际弹出了系统窗口，不能算静默测试通过；加入旧钥匙串控制后，三个独立读取及原生条目读写测试约 0.1 秒完成，没有再次要求授权，测试条目已清理。
- Release 回归：66 项 UI/逻辑通过、3 项默认跳过；26 项本地 SSH 检查无非预期失败，仍有 1 项已知 libssh2 尾部输出 XFAIL。SSH 解锁、连接测试解锁、RDP 解锁三个模拟凭据用例另在原生 Cocoa 下通过。

## v0.2.64 旧钥匙串条目读取兼容

- 根因：v0.2.62 将读取程序从 `/usr/bin/security` 改成临时签名的应用自身；旧条目原有的读取授权不自动授予新程序。v0.2.63 处理了重入，但没有修复此兼容性回归。
- 只检查所请求条目的引用和 decrypt ACL，不读取其他条目的密码；确认其信任固定路径 `/usr/bin/security` 才沿用旧读取方式。元数据查询禁止弹窗，不先尝试原生读取后再回退。
- 子进程只接收服务名、随机账号引用和输出标志 `-w`，不接收密码；结果经私有 stdout 管道回到内存，不进入日志。失败不更换读取程序重试，等待上限 30 秒，接收的凭据数据限制为 1 MiB。
- 新建/更新仍用原生 Security API，不放宽 ACL、不增加信任程序、不批量迁移、不解锁钥匙串、不增加密码缓存。原生创建的条目继续原生读取。
- 使用真实系统钥匙串中的随机虚拟条目，复现旧程序创建的 ACL；禁止测试进程显示授权 UI 时，修复前读取失败，修复后连续三次读取通过。另验证新式原生条目的读写更新删除；没有读取或改动真实服务器密码。
- 系统钥匙串锁定、访问权限被更改或原生条目在应用签名变化后仍可能要求合法授权；本版不是 Developer ID 签名/公证，不声称消除一切系统安全提示。

## v0.2.62 的采样策略

仅当前选中且已连接的会话自动采样，不增加 SSH 连接，不部署远端守护进程。
监控仍有少量 CPU/SSH 开销，不能保证服务器完全零负载。

| 内容 | 前台间隔 | 降低开销的方式 |
| --- | --- | --- |
| CPU、内存、负载、运行时间、网卡 | 1 秒 | 优先用一个 awk 读取 /proc，缺少 awk 时兼容原有基础命令；核心数从 /proc/stat 推导 |
| CPU/内存进程排行 | 5 秒 | 两个排行都保留，不再每秒重复执行两次 ps |
| 磁盘占用 | 30 秒 | 仅本地文件系统，避免 df 触碰卡住的网络挂载 |

后台、最小化或隐藏监控区域时，基础指标间隔为 5 秒。慢速指标在未到刷新时间时保留最近结果，
并不代表其值是当前这一秒的实时读数。采样失败时按 2、4、8、16、30 秒退避；恢复成功后返回正常间隔。
同一会话不堆积并行采样；同一路径已有未完成目录请求时合并请求，完成后仍可主动刷新。
切回已有标签先显示该会话的最近采样及原始采样时间，不为填补界面空白突发追加远端查询。

按每秒请求、持续 60 秒的调度测试，进程排行采集由 60 轮降为 12 轮，磁盘由 60 次降为 2 次。
这代表命令频次降低约 80% 和 96.7%，**不是服务器 CPU 占用降低比例**。

采样数据最多 512 KiB，读取受超时及取消约束。终端搜索输出刷新最多每 100 毫秒一次，
搜索词变更与前后跳转即时处理；不丢弃终端数据来伪造流畅。

## 凭据与连接

macOS 读写通过 Security 框架操作 Keychain，不把编码后的密码放入子进程命令行。
v0.2.66 在 v0.2.65 移除 `security` 读取兼容路径的基础上，彻底移除授权模式，全部原生操作禁止交互。
沿用既有 `com.noxshell.ops.ssh` 服务名及序列化格式，不批量迁移或删除条目。
不可读的旧条目由用户重新输入 SSH 凭据；成功认证后按用户选择保存为新条目并更新引用。
不会降级到明文存储，也不会把其他条目的凭据拿来尝试。

会话公开元数据不保留密码/私钥口令，worker 在认证结束或清理连接时释放相应副本。
这不意味着可以保证所有内存、交换区或系统库中的历史副本已被安全擦除。
未知指纹仍需用户确认，已知指纹变化仍阻断；不自动重放失败命令，不降低 SSH 算法安全性。

## 验证与边界

- UI/逻辑测试使用临时数据库，SSH 集成测试使用回环地址、随机端口和虚构凭据。
- 原生 Keychain 测试需显式设置 `NOXSHELL_TEST_NATIVE_KEYCHAIN=1`；只操作随机 `noxshell-test-` 条目，测试结束删除，不接触真实条目。
- 回归覆盖正常及超量指标后继续终端交互、重连、指纹变更、认证超时、密钥重新协商等；不代表各 Linux 发行版的实机测试。
- libssh2 1.11.1 的“大量尾部输出后立即关闭 TCP”问题仍是明确的 XFAIL，详见 `tests/auth_fixture/README.md`。
- 监控/SFTP 目前仍共用会话 worker，慢远端操作仍可能短暂延迟终端输入；本轮降低操作频次与重复请求，没有宣称所有操作均完全异步。
- 实际连接速度仍取决于正确的 IP/端口、DNS、网络、服务端认证及登录脚本；本轮不修改真实服务器参数。
- 本机 Homebrew 依赖可能要求 macOS 26，本机验证包不能当作已经验证 macOS 14 兼容的公共发行包；公开发布仍应使用 CI 平台依赖并完成签名/公证检查。
