# 性能与安全说明

## v0.2.62 的采样策略

仅当前选中且已连接的会话自动采样，不增加 SSH 连接，不部署远端守护进程。
监控仍有少量 CPU/SSH 开销，不能保证服务器完全零负载。

| 内容 | 前台间隔 | 降低开销的方式 |
| --- | --- | --- |
| CPU、内存、负载、运行时间、网卡 | 1 秒 | 优先用一个 awk 读取 /proc，缺少 awk 时兼容原有基础命令；核心数从 /proc/stat 推导 |
| CPU/内存进程排行 | 5 秒 | 两个排行都保留，不再每秒重复执行两次 ps |
| 磁盘占用 | 30 秒 | 仅本地文件系统，避免 df 触碰卡住的网络挂载 |

后台、最小化或隐藏监控区域时，基础指标间隔为 5 秒。慢速指标在未到刷新时间时保留最近结果，
并不代表其值是当前这一秒的实时读数。采样失败时按 2、4、8、16、30 秒退避；恢复成功后返回正常间隔。
同一会话不堆积并行采样；同一路径已有未完成目录请求时合并请求，完成后仍可主动刷新。
切回已有标签先显示该会话的最近采样及原始采样时间，不为填补界面空白突发追加远端查询。

按每秒请求、持续 60 秒的调度测试，进程排行采集由 60 轮降为 12 轮，磁盘由 60 次降为 2 次。
这代表命令频次降低约 80% 和 96.7%，**不是服务器 CPU 占用降低比例**。

采样数据最多 512 KiB，读取受超时及取消约束。终端搜索输出刷新最多每 100 毫秒一次，
搜索词变更与前后跳转即时处理；不丢弃终端数据来伪造流畅。

## 凭据与连接

macOS 通过 Security 框架操作 Keychain，不再把编码后的密码放入子进程命令行。
沿用既有 `com.noxshell.ops.ssh` 服务名、账号引用及序列化格式，不批量迁移或删除条目。
第一次访问旧条目可能由 macOS 要求授权；仅确认应用身份后授权。取消或拒绝会明确报错，
不会降级到明文存储，也不会把其他条目的凭据拿来尝试。

会话公开元数据不保留密码/私钥口令，worker 在认证结束或清理连接时释放相应副本。
这不意味着可以保证所有内存、交换区或系统库中的历史副本已被安全擦除。
未知指纹仍需用户确认，已知指纹变化仍阻断；不自动重放失败命令，不降低 SSH 算法安全性。

## 验证与边界

- UI/逻辑测试使用临时数据库，SSH 集成测试使用回环地址、随机端口和虚构凭据。
- 原生 Keychain 测试需显式设置 `NOXSHELL_TEST_NATIVE_KEYCHAIN=1`；只操作随机 `noxshell-test-` 条目，测试结束删除，不接触真实条目。
- 回归覆盖正常及超量指标后继续终端交互、重连、指纹变更、认证超时、密钥重新协商等；不代表各 Linux 发行版的实机测试。
- libssh2 1.11.1 的“大量尾部输出后立即关闭 TCP”问题仍是明确的 XFAIL，详见 `tests/auth_fixture/README.md`。
- 监控/SFTP 目前仍共用会话 worker，慢远端操作仍可能短暂延迟终端输入；本轮降低操作频次与重复请求，没有宣称所有操作均完全异步。
- 实际连接速度仍取决于正确的 IP/端口、DNS、网络、服务端认证及登录脚本；本轮不修改真实服务器参数。
- 本机 Homebrew 依赖可能要求 macOS 26，本机验证包不能当作已经验证 macOS 14 兼容的公共发行包；公开发布仍应使用 CI 平台依赖并完成签名/公证检查。
